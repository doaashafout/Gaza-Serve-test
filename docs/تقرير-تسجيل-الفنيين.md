# تقرير: آلية تسجيل الفنيين في بوت غزة سيرف

## المشكلة
نظراً لضعف أو انقطاع الإنترنت في قطاع غزة، كان لا بد من اختيار آلية تسجيل للفنيين تستهلك أقل قدر ممكن من بيانات الهاتف وتعمل بأقل سرعات النت.

## الخيارات المطروحة

### الخيار 1: Telegram Web App (نموذج ويب داخل البوت)
- **الوصف**: صفحة HTML تفتح داخل Telegram كـ WebView عند الضغط على زر
- **الإيجابيات**: واجهة مستخدم أجمل، حقول متعددة في صفحة واحدة، رفع صور مباشر
- **السلبيات**:
  - يحتاج رابط HTTPS عام ليعمل (يتطلب ngrok أو استضافة خارجية)
  - يستهلك بيانات أكثر (تحميل صفحة كاملة + خطوط خارجية + رفع صور)
  - اعتماد على اتصال إنترنت مستقر
  - لا يعمل بدون `SERVER_URL`

### الخيار 2: محادثة نصية تفاعلية (Step-by-step)
- **الوصف**: أسئلة متسلسلة داخل محادثة Telegram، يجيب المستخدم على كل سؤال
- **الإيجابيات**:
  - يستهلك بيانات ضئيلة جداً (نصوص فقط + إيموجي)
  - يعمل على أبطأ سرعات الإنترنت
  - لا يحتاج أي إعدادات خارجية (لا ngrok ولا سيرفر عام)
  - يعمل مباشرة عند تشغيل البوت
  - عبر 4 خطوات فقط: الاسم ← الهاتف ← التخصص ← المنطقة
- **السلبيات**:
  - واجهة أقل جمالاً من الـ Web App
  - لا يدعم رفع الصور مباشرة
  - تجربة مستخدم أقل سلاسة

## القرار النهائي
تم اعتماد **المحادثة النصية التفاعلية** للأسباب التالية:
1. استهلاك بيانات منخفض جداً (نصوص فقط)
2. لا حاجة لإنترنت عالي السرعة
3. لا حاجة لإعدادات خارجية (ngrok, domains, SSL)
4. يعمل فوراً عند تشغيل البوت محلياً
5. يخدم المستخدمين في ظروف الحصار وانقطاع الكهرباء والنت

## الأدوات التي تم استخدامها ولم تنجح
- **ngrok** – لإعطاء السيرفر المحلي رابط HTTPS عام
- **Telegram Web App API** – لفتح نموذج ويب داخل البوت
- تم تنفيذ الصفحة (`register.html`) والـ API (`/api/register/technician`) ولكن لم يتم تفعيلها نهائياً بسبب استهلاك البيانات

## هيكل التدفق الحالي (الأخير)

```
/register
  ↓
الخطوة 1: الاسم الثلاثي (نص)
  ↓
الخطوة 2: رقم الهاتف (نص)
  ↓
الخطوة 3: التخصص (أزرار اختيار)
  ↓
الخطوة 4: المنطقة (أزرار اختيار)
  ↓
✅ تم التسجيل كفني
```
